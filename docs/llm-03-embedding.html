03. 向量与 Embedding：把文字变成数学

Token ID 只是编号，模型还需要把它查成一串向量，才能在数学空间里计算相似、关系和上下文。

EmbeddingVectorSimilarity
从场景开始 直接看演示

Scenario

为什么需要这一讲

模型看到 Paris 不是看到一个城市名字，而是看到一串向量。向量之间的距离和方向，承载了“相似”“相关”“语义靠近”等信息。

Mental Model

先建立一个直觉

Embedding 像给每个 token 发一张数学身份证：不是写着姓名，而是写着一串特征坐标。

  32 def get_vector(word):
  33     """获取一个词的 Embedding 向量，自动处理带/不带空格的变体"""
  34     for variant in [word, " " + word, word.lower(), " " + word.lower(),
  35                     word.capitalize(), " " + word.capitalize()]:
  36         ids = tokenizer.encode(variant)
  37         if len(ids) == 1:
  38             return embedding_table[ids[0]], ids[0], variant.strip()
  39     ids = tokenizer.encode(word)
  40     return embedding_table[ids[0]], ids[0], tokenizer.decode([ids[0]]).strip()

  44     return torch.dot(v1, v2) / (v1.norm() * v2.norm())

用余弦相似度比较语义距离

向量之间可以算距离，距离越近，模型越容易把它们看成相关。

运行观察

从向量形状、相似度和一词多义三个角度理解 Embedding。

演示命令

python3 llm/03-embedding/embedding.py "France" "Paris" "Germany" "Berlin" "cat" "dog"
python3 llm/03-embedding/context_embedding.py
  • embedding.py 会打印 Embedding 表形状：词表大小 × 向量维度。
  • 语义相关的词通常会有更高相似度，例如国家和首都、动物和动物。
  • context_embedding.py 会展示同一个 bank 在不同上下文中经过 Transformer 后向量发生变化。
  • 固定 Embedding 是起点，真正的语境理解发生在后续层里。

Try It

自己试一轮

用“身份证坐标”解释 Embedding，再用相似度输出验证它确实能表达关系。

  1. 换几组词，例如 doctor、hospital、music，观察相似度。
  2. 运行 context_embedding.py，重点看 bank 的 Embedding 层和最后一层差异。
  3. 打开代码中的 embedding_table.shape，对应理解“词表大小 × 向量维度”。

Takeaway

这一讲看懂什么

  • Embedding 把 token ID 变成可计算的向量。
  • 向量相似度可以表达粗粒度语义关系。
  • 同一个 token 的最终表示会被上下文改写。

Key Points

讲解要点

  • 模型不能直接算文字，只能算数字向量。
  • Embedding 表本质上是一张大查找表。
  • 上下文感知不是 Embedding 单独完成的，而是 Transformer 层逐步加工的结果。

Pitfalls

容易误解

  • 不要把向量维度理解成可人工命名的属性列，它们通常不是人类可读字段。
  • 向量相似不等于事实正确，只表示表示空间里的接近。
  • 静态 Embedding 无法单独解决一词多义。
