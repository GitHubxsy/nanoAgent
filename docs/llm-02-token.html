02. Token：大模型眼中的“字”长什么样

模型不直接读取中文、英文或代码，而是先把文本切成 token，再把 token ID 送入模型。

TokenBPETokenizer
从场景开始 直接看演示

Scenario

为什么需要这一讲

同一句话，在人眼里是自然语言；在模型眼里，是一串数字 ID。为什么中文、代码、URL 更容易吃掉上下文？答案往往从分词开始。

Mental Model

先建立一个直觉

Token 像模型的拼图块：常见片段可以是一整块，不常见片段会被拆成更多小块。

统计相邻片段

BPE 的第一步很朴素：数一数哪些相邻片段最常一起出现。

看 GitHub 行号 
  17 def get_pairs(tokens_list):
  18     """统计所有相邻 token 对的出现次数"""
  19     pairs = Counter()
  20     for tokens in tokens_list:
  21         for i in range(len(tokens) - 1):
  22             pairs[(tokens[i], tokens[i + 1])] += 1
  23     return pairs

逐轮合并高频片段

高频片段被合并成新 token，词表就是这样一点点训练出来的。

看 GitHub 行号 
  43 def train_bpe(text, num_merges=10):
  44     """
  45     训练一个最简 BPE 分词器。
  46
  47     参数：
  48         text: 训练文本
  49         num_merges: 合并几次（决定最终词表大小）
  50
  51     返回：
  52         vocab: 最终词表
  53         merge_rules: 合并规则列表（按顺序）
  54     """
  55     # 把每个词拆成单个字符 + 词尾标记
  56     words = text.split()
  57     tokens_list = [list(word) + ["</w>"] for word in words]
  58
  59     # 初始词表
  60     vocab = set()
  61     for tokens in tokens_list:
  62         vocab.update(tokens)
  63
  64     print(f"训练文本: '{text}'")
  65     print(f"词的数量: {len(words)}")
  66     print(f"初始词表 ({len(vocab)} 个): {sorted(vocab)}")
  67     print(f"\n开始 BPE 合并（共 {num_merges} 轮）：")
  68     print("=" * 65)
  69
  70     merge_rules = []
  71
  72     for step in range(num_merges):
  73         pairs = get_pairs(tokens_list)
  74         if not pairs:
  75             print(f"\n  轮次 {step + 1}: 没有更多的 pair 可以合并了，提前停止")
  76             break
  77
  78         best_pair = pairs.most_common(1)[0]
  79         pair, count = best_pair
  80         new_token = pair[0] + pair[1]
  81
  82         print(f"\n  轮次 {step + 1}: 合并 ('{pair[0]}', '{pair[1]}') → '{new_token}'  "
  83               f"（出现 {count} 次）")
  84
  85         tokens_list = merge_pair(tokens_list, pair, new_token)
  86         vocab.add(new_token)
  87         merge_rules.append((pair, new_token))

Live Demo

运行观察

用分词结果解释：为什么同样长度的文本，在模型里成本和难度可能完全不同。

演示命令

python3 llm/02-token/tokenizer_demo.py "Kubernetes is awesome"
python3 llm/02-token/tokenizer_demo.py "你好世界"
python3 llm/02-token/bpe_demo.py --merges 8
  • tokenizer_demo.py 会展示文本被切成哪些 token，以及对应的 token ID。
  • 中英文、代码、URL 的 token 数量差异会很明显。
  • bpe_demo.py 会逐轮合并高频片段，展示词表是怎么长出来的。
  • 没见过的新词也能被已有 token 拼出来，这就是子词分词的价值。

Try It

自己试一轮

先让大家亲眼看到：同一段文字进入模型前，已经被改写成一串 token ID。

  1. 输入一段中文、一段英文、一段代码，对比 token 数。
  2. 把 --merges 从 5 改到 15，观察词表变大后分词如何变粗。
  3. 尝试 URL 或 JSON，观察它们为什么容易消耗更多 token。

Takeaway

这一讲看懂什么

  • Token 是模型真正处理的基本单位。
  • BPE 的核心是不断合并高频相邻片段。
  • Token 数影响上下文长度、费用和推理开销。

Key Points

讲解要点

  • 模型不是看字符，而是看 token ID。
  • 分词器决定模型第一眼看到的世界长什么样。
  • Token 是后续 Embedding、Attention、上下文窗口和计费的共同入口。

Pitfalls

容易误解

  • Token 不等于中文汉字，也不等于英文单词。
  • 字符数少不代表 token 少，尤其是代码、符号和 URL。
  • 不同模型的分词器不同，token 数也会不同。
