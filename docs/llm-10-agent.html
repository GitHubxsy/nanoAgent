Scenario

为什么需要这一讲

模型可以写出“我会创建文件”，但不会真的创建文件。要让它动手，需要把工具说明发给模型，并由外部代码执行工具调用。

Mental Model

先建立一个直觉

LLM 像大脑，工具像手，循环像“看结果再决定下一步”的工作节奏。三者合在一起，才是最小 Agent。

Agent 核心循环

模型决定是否调用工具，代码执行工具，再把结果写回消息历史进入下一轮。

看 GitHub 行号 
 136 # ==================== 4. Agent 核心循环 ====================
 137
 138
 139 def run_agent(user_message, max_steps=10):
 140     """
 141     Agent 的完整循环：
 142     1. 把用户消息发给 LLM
 143     2. LLM 输出文本 → 返回给用户，结束
 144     3. LLM 输出工具调用 → 执行工具 → 把结果加入消息历史 → 回到 1
 145     """
 146     messages = [
 147         {"role": "system", "content": "You are a helpful assistant. Be concise."},
 148         {"role": "user", "content": user_message},
 149     ]
 150
 151     for step in range(max_steps):
 152         print(f"\n\033[36m[Step {step + 1}]\033[0m 调用 LLM... ", end="", flush=True)
 153
 154         # ---- 让大模型“想” ----
 155         # 这一步背后发生的事情：
 156         #   分词(第2篇) → Embedding(第3篇) → Attention(第4篇)
 157         #   → Transformer×N层(第5篇) → 逐token输出(第7篇)
 158         #   上下文窗口在增长(第8篇)，模型越大越准(第9篇)
 159         response = client.chat.completions.create(
 160             model=MODEL,
 161             messages=messages,
 162             tools=tools,
 163         )
 164
 165         choice = response.choices[0]
 166         assistant_msg = choice.message
 167
 168         # 把模型的回复加入消息历史
 169         messages.append(assistant_msg)
 170
 171         # ---- 判断：输出文本还是工具调用？ ----
 172         if not assistant_msg.tool_calls:
 173             # 模型输出了普通文本 → 任务结束
 174             print("回复文本")
 175             print(f"\n\033[32m{assistant_msg.content}\033[0m")
 176             return assistant_msg.content
 177
 178         # ---- 模型输出了工具调用 → 让代码去“做” ----
 179         for tool_call in assistant_msg.tool_calls:
 180             func_name = tool_call.function.name
 181             func_args = json.loads(tool_call.function.arguments)
 182
 183             print(f"调用工具 {func_name}({func_args})")
 184
 185             # 执行工具
 186             if func_name in available_tools:
 187                 result = available_tools[func_name](**func_args)
 188             else:
 189                 result = f"未知工具: {func_name}"
 190
 191             # 打印工具返回（截断过长的输出）
 192             display = result[:200] + "..." if len(result) > 200 else result
 193             print(f"  \033[33m→ {display}\033[0m")
 194
 195             # 把工具结果加入消息历史，让模型在下一轮看到
 196             messages.append(
 197                 {
 198                     "role": "tool",
 199                     "tool_call_id": tool_call.id,
 200                     "content": result,
 201                 }
 202             )
 203
 204     print("\n达到最大步数，停止。")
 205     return None

运行观察

把前九讲的模型机制接到 Agent：模型负责决策，代码负责执行，结果再回到上下文。

演示命令

python3 llm/10-agent/tiny_agent.py "查看当前目录下有哪些文件"
  • 脚本需要 OPENAI_API_KEY 和可选 OPENAI_BASE_URL。
  • 运行时会打印 [Step] 调用 LLM，然后看到模型是否选择工具。
  • 当模型调用 execute_bash、read_file 或 write_file 时，真正执行的是 Python 函数。
  • 工具结果会作为 tool 消息写回上下文，模型据此进入下一轮。

Takeaway

这一讲看懂什么

  • LLM 只输出意图，外部代码负责执行动作。
  • 工具说明进入模型上下文，工具实现留在程序里。
  • Agent 是 LLM 能力的工程延伸，不是另一个神秘物种。

Key Points

讲解要点

  • 前九讲解释模型怎么生成 token，第十讲解释如何让 token 变成行动。
  • Tool schema 是模型能看到的能力说明书。
  • 循环让 Agent 可以多步执行、观察结果、继续修正。

Pitfalls

容易误解

  • 不要以为模型自己执行了命令，执行权始终在外部代码。
  • 工具越强，越需要权限、安全和可观测性。
  • Agent 的质量仍然受上下文、模型能力和工具设计影响。
