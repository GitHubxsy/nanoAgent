09. Scaling Law：为什么“大力出奇迹”有效

Scaling Law 描述模型规模、数据规模、计算量和 Loss 之间的经验关系，解释了为什么更大模型通常更强。

Scenario

为什么需要这一讲

为什么行业不断把模型做大、数据做多、算力堆高？不是因为迷信规模，而是经验上规模扩大后 Loss 会按规律下降。

Mental Model

先建立一个直觉

Scaling Law 像工程里的压测曲线：不是保证每次都线性变好，但能告诉你继续投入规模时，大概率会往哪个方向走。

在 log-log 空间看趋势

Scaling Law 常用对数坐标观察，因为规模变化通常跨越多个数量级。

看 GitHub 行号 
 219     # 简单线性回归计算斜率
 220     n = len(log_params)
 221     mean_x = sum(log_params) / n
 222     mean_y = sum(log_losses) / n
 223     numerator = sum((x - mean_x) * (y - mean_y) for x, y in zip(log_params, log_losses))
 224     denominator = sum((x - mean_x) ** 2 for x in log_params)
 225     slope = numerator / denominator if denominator != 0 else 0
 226     intercept = mean_y - slope * mean_x
 227
 228     print("\n  Log-Log 线性回归:")
 229     print(f"    斜率 α = {-slope:.3f} (Scaling Law 中 L ∝ N^(-α))")
 230     change_pct = (10 ** slope - 1) * 100
 231     direction = "下降" if slope < 0 else "上升"
 232     print(f"    即参数量每增长 10 倍, Loss {direction}约 {abs(change_pct):.0f}%")

运行观察

用几个不同大小的微型模型，观察参数量增加时 Loss 的整体趋势。

演示命令

python3 llm/09-scaling-law/scaling_law.py --steps 50
  • 脚本会训练多组不同参数量的小模型。
  • 结果表会打印参数量、Loss、log 参数量和 log Loss。
  • 如果训练步数足够，通常能看到更大模型 Loss 更低的趋势。
  • 这个实验只演示趋势，不等同于真实大模型训练结论。

Try It

自己试一轮

用小实验解释趋势，用边界提醒大家不要把规模神化。

  1. 先用 --steps 50 快速观察，再改成 200 看趋势是否更稳定。
  2. 查看 configs，理解每个模型规模差异来自哪里。
  3. 观察 log-log 输出，理解为什么 Scaling Law 常用对数图表示。

Takeaway

这一讲看懂什么

  • 模型能力提升常常来自参数、数据和算力共同扩大。
  • Scaling Law 关注的是趋势，不是某一次实验的绝对值。
  • 规模带来能力，也带来训练、推理、成本和安全问题。

Key Points

讲解要点

  • “大力出奇迹”背后是可观察的经验规律。
  • 参数量不是唯一变量，数据量和计算量同样关键。
  • 真实系统要在效果、成本、延迟之间做取舍。

Pitfalls

容易误解

  • 不要把小实验的数字当成真实大模型定律，只看趋势。
  • 模型变大并不自动解决数据质量和对齐问题。
  • 规模收益会有边际成本，工程上必须算账。
