06. 训练：参数是怎么“学”出来的

训练就是不断预测、计算误差、反向传播、更新参数，让模型逐渐降低 Loss。

Scenario

为什么需要这一讲

刚初始化的模型像一台乱猜的机器。训练的目标不是给它写规则，而是让它在大量样本上反复试错，把参数调到更容易猜对的位置。

Mental Model

先建立一个直觉

训练像调音台：Loss 告诉你声音偏了多少，梯度告诉你每个旋钮往哪边拧，优化器负责真的拧一下。

训练循环

训练的关键动作都在这里：取样、前向、算 Loss、反向传播、更新参数。

看 GitHub 行号 
 172 for step in range(n_steps):
 173     # 随机抽取训练片段
 174     ix = torch.randint(0, len(data) - seq_len - 1, (batch_size,))
 175     x = torch.stack([data[i:i+seq_len] for i in ix])       # 输入
 176     y = torch.stack([data[i+1:i+seq_len+1] for i in ix])   # 正确答案（下一个字符）
 177
 178     # 前向传播：预测
 179     logits = model(x)
 180
 181     # 计算 Loss（本篇第三节）
 182     loss = F.cross_entropy(logits.view(-1, vocab_size), y.view(-1))
 183
 184     # 反向传播：算梯度（本篇第四节）

 186     loss.backward()

运行观察

用一个微型模型现场看到 Loss 下降，以及模型从乱猜到能续写训练句子。

演示命令

python3 llm/06-training/train_tiny.py
  • 启动时会打印训练数据长度、词表大小和模型参数量。
  • 训练过程中每隔一段时间打印 Loss，通常会看到整体下降。
  • 训练后用几个 prompt 生成文本，能看到模型学到了训练语料里的模式。
  • 这个小模型不是为了好用，而是为了看清训练循环。

Try It

自己试一轮

用 Loss 曲线把“学习”讲成一个可以观察的工程过程。

  1. 把 n_steps 从 500 调小到 100，观察 Loss 是否下降得不够充分。
  2. 改几句训练文本，再看生成结果是否更偏向新语料。
  3. 对照 TinyTransformer，回看 Embedding、Attention、FFN 如何接在一起。

Takeaway

这一讲看懂什么

  • 训练的核心闭环是预测、算 Loss、反向传播、更新参数。
  • Loss 下降表示模型在训练数据上越来越不离谱。
  • 真实大模型训练只是规模巨大，本质闭环并没有变。

Key Points

讲解要点

  • 模型参数不是人工写出来的，而是通过优化不断调出来的。
  • 训练数据决定模型能学到什么，也决定它容易重复什么。
  • 小模型能演示机制，但不能代表真实大模型的能力边界。

Pitfalls

容易误解

  • Loss 低不等于真实世界表现一定好，可能只是记住训练数据。
  • 训练不是一次完成，大模型通常还有预训练、指令微调、偏好对齐等阶段。
  • 不要把训练和推理混为一谈，训练会更新参数，推理通常不更新参数。
